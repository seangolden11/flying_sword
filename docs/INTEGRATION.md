# Flying Sword 통합 구현 및 검증 현황

기준: 2026-11-05. 사용자 승인 규칙을 반영한 코드·에셋 연결 현황이다. 실제 Unity Play Mode 검증 완료를 의미하지 않는다.

## 구현된 연결

| 범위 | 구현 |
| --- | --- |
| 성장 | 중복 없는 동일 확률 추첨, 화면당 리롤 1회, 삭제/복사/공격력/회수/호밍, 무기 대상 선택과 뒤로 가기 |
| 신규 무기 | 조각검·쓰레기통·테이블·모니터·펜싱칼·세탁기 각각 공전·투척·설치·회수에 연결 |
| 시너지 | 전격 작업대 / 파편 성검. 약한 강화→이른 획득 순으로 종류별 1개 소모, 새 기본 능력으로 공전 생성 |
| 일시 합체 | 실제 구성품 보존, 피해 합산·능력 종류별 결합·공통 호밍, 구성품 강화/복사/삭제, 복귀 분해 후 시너지 검사 |
| 스킬 | 보상으로 1·2·4 해금, 중복 해금 제외, 3·5 잠금 유지, 검막 무기별 재타격 간격 및 탄환 차단 |
| 패시브 | 접촉 반격 1/10초, 획득 이후 10킬당 HP 1, HP 10 상한 |
| 난이도 | 적 HP 고정(근접 2/원거리 1), 시간별 등장 마릿수 증가 |
| UI | Input System 전용 환경용 uGUI 선택·리롤·대상 목록, 정지/재개, 보유 무기 요약, R 입력 미사용 |
| 아트 | image_gen으로 생성한 최종 PNG 24종, Resources 로드와 Sprite 임포트 설정, 효과·카드·무기에 연결 |

회수 공격은 특수 효과를 재발동하지 않는다. 전기 폭발은 직접 명중한 적에게 중복 피해를 주지 않는다. 세탁기는 설치 순간 주변 적에게 무피해 넉백을 주며 무기·타이머는 건드리지 않는다. 조각검 분신은 원본당 2개가 독립적으로 반복 공격하고 원본 회수 시작 시 정리된다. 상위 무기와 일시 합체는 다른 규칙이다.

## Inspector 테스트 기본값

| 종류 | 피해 | 비행 속도 | 넉백 속도 |
| --- | --- | --- | --- |
| 기본 검 | 1 | 16 | 6 |
| 조각검 | 1 | 16 | 6 |
| 쓰레기통 | 1 | 13 | 6 |
| 테이블 | 2 | 8 | 14 |
| 모니터 | 1 | 13 | 6 |
| 펜싱칼 | 1 | 18 | 6 |
| 세탁기 | 1 | 11 | 6 |
| 전격 작업대 | 3 | 20 | 14 |
| 파편 성검 | 2 | 36 | 6 |

- 추가 호밍: 반경 4, 최대 1.2초, 다른 적 1회.
- 분신: 원본당 2개, 피해 1, 반경 3.5, 속도 12, 타격 간격 0.6초. 원본 회수까지 유지하며 재귀 소환 없음.
- 전기 폭발: 반경 1.7, 주변 적 피해 1.
- 세탁기: 설치 순간 무피해 넉백, 반경 2.8, 속도 20, 넉백 0.35초.
- 검막: 같은 적에 대한 무기별 간격 0.5초.
- 스폰: 기본 3초 간격 고정, 120초마다 등장 마릿수 1 증가. 기존 적 비율 유지.

위 값은 Inspector에서 조절하는 테스트용 기본값이며 최종 밸런스가 아니다. 곡선 유도 기본값은 거리 5/감지 반각 45도/초당 240도다. 포착 대상을 유지하되 최초 발사 방향 85도 밖이면 해제하며, 기존 비행 거리와 화면 경계 제한을 유지한다.

빌드 로그: `validation/csharp-build.log`. Unity 시작 로그: `validation/unity-startup.log`. 아트 검사: `validation/art-validation.json`.

Unity 배치 실행은 권한 확장 재시도에서 LicenseClient 연결 후 프로젝트 경로 설정 직후 종료 코드 1로 끝났다. 스모크 체크 성공 로그가 없으므로 실행 성공으로 처리하지 않는다. 종료 원인은 이 로그만으로 확정할 수 없다.

## 실행할 통합 체크

Unity Hub에서 6000.3.22f1로 프로젝트를 열고 SampleScene을 Play한 다음 `Flying Sword > Run Survival Smoke Check`를 실행한다. 활성 보상 화면을 먼저 닫고 실행한다. 배치 실행은 `-batchmode -nographics -projectPath <project> -executeMethod SurvivalSmokeCheck.RunBatch -logFile <log>`이며 `-quit`를 붙이지 않는다. 도메인 리로드 이후 실행을 이어가도록 SessionState를 사용한다.

체크는 기존 전투 회귀, 모든 신규 무기, 회수 특수 효과 분리, 조각 정리, 시너지의 우선 소모/중복 방지, 일시 합체 데이터 보존, 구성품 강화/복사/삭제, 해금 제외, 반격/회복, 레벨업 후 기존·신규 적 HP 고정, 아트 24종 로드, 네이티브 UI 생성과 카드 콜백을 포함한다. 실제 마우스 이벤트·화면 배치·체감 밸런스는 별도 플레이 확인이 필요하다.

## 이미지와 입력 출처

이미지는 내장 image_gen으로 실제 생성했다. 모든 생성 프롬프트와 합체 아이콘 수정 프롬프트는 Assets/Resources/Art/generation-prompts.json에 있다. Point 필터, PPU 64, 최대 텍스처 64, 무압축 알파 Sprite로 설정했다. 원본 고해상도 PNG는 보존한다.

Input System 전용 설정에서 IMGUI 런타임 입력이 지원되지 않는 문제 때문에 프로젝트 설정을 바꾸는 대신 보상 입력을 uGUI와 InputSystemUIInputModule로 연결했다. 근거: [Unity 공식 Input System 문서](https://github.com/Unity-Technologies/InputSystem/blob/develop/Packages/com.unity.inputsystem/Documentation~/use-imgui-alongside-input-system.md).

## Editor 연결 후 크기 수정

열린 Unity Editor에 연결해 Play 화면에서 검이 과도하게 큰 현상을 실제 확인했다. 생성 PNG의 Sprite bounds와 PPU를 고려하지 않은 localScale이 원인이었다. GameArt.WorldScale로 실제 bounds를 정규화하고 일반 무기 최대 길이 1.5, 분신 0.75, 효과 지정 범위에 적용했다. 재컴파일 후 Play 화면에서 기본 검 3개의 정상 크기를 확인했다. 전체 무기·보상·시너지 통합 테스트 실행은 여전히 별도 검증이 필요하다.

## 공통 호밍 및 합체 투척 속도 변경

호밍 보상은 모든 현재·미래 무기에 적용하는 공통 강화다. 대상 선택 없이 즉시 적용하고 최대 3단계에서 추첨을 제외한다. 단계당 거리 +0.25, 각도 +5도, 회전 +10도/초는 유지한다. 무기별 호밍 저장·복사·합산은 제거했다. 시너지 재료 소모 우선순위는 개별 공격력 강화와 획득 ID로 판단한다.

일시 합체와 두 시너지 무기의 투척 속도를 기존 계산값의 2배로 조정했다. 구성품의 기본 속도를 먼저 계산하고 마지막에 한 번만 배율을 적용한다. 회수·튕김 속도와 일반 무기 속도는 변경하지 않았다. 위 표의 시너지 속도는 배율 적용 후 값이며 Inspector 기본 프로필은 10/18이다.

한 번에 등장하는 마릿수는 레벨이 아니라 생존 시간에 따라 증가합니다. 테스트 기본값은 0~119초 1마리, 120~239초 2마리, 240~359초 3마리입니다. Inspector의 Initial Spawn Count(1), Spawn Count Growth Interval(120초), Additional Enemies Per Time Step(1)로 조절합니다. 보상 선택·일시정지·게임오버 중에는 생존 시간이 누적되지 않습니다. 레벨별 스폰 가속은 제거했습니다. 적 HP와 근접·원거리 비율은 유지합니다.
